# 阶段 4 · 标准答案

1. 清算、风控硬规则、下单状态机、对账：确定图 + 局部 LLM。Multi-Agent 适合目标模糊、需要工具探索的投研。混用时规则节点不要交给模型改写。

2. 职责污染：无法单独评测子能力、无法替换数据层、失败无法定位。正确：plan → 调用有契约的子 Agent → 汇总 bundle。

3. 重发聊天：重复工具副作用、重复花钱、顺序漂移。checkpoint：状态机游标 + 已产出的 JSON 落库，从失败节点重试。

4. 丢失待批准项或重复触发。HITL 必须外置状态 + 票据 id。

5. 生产上应 **暴露冲突**（结构化 disagreements[]），不要静默调和成「强烈推荐」。调和是人的工作或明确的仲裁策略。

6. API → 任务表 → Worker → Supervisor plan → 子 Agent → 写 bundle → 条件边 → WAIT_HUMAN 持久化。
