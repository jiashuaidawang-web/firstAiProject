# 阶段 2 · 标准答案

1. 默认不住。每次 Prompt 是你显式组装的。生产记忆在 Redis/DB（或 Spring AI 的 Memory Store 背后的外置实现）。进程内 Map 扩容即丢、无法多实例。

2. 两个请求同时 append，后写覆盖先写或 list 乱序，用户看到「我说的那句没了」或工具结果交错。锁或单分区队列保证 append 线性。量化上「同一研究任务」比「同一用户所有聊天」更合适做锁粒度。

3. 窗口：保近因，控 token。摘要：保远因，损细节。假设表：保可执行事实（标的、方向、待验证点），应用代码可读。K 线进数据库/工具，不进聊天记忆。

4. 两种都成立：不落半句（实现简单，用户重试）；或落 `partial=true` 便于续写。不要把半句当完整结论给下游 Agent。

5. 不该无审核写入长期记忆。这是指令覆盖/投毒。短期会话可以存在当前 thread，长期画像要白名单字段。

6. 时序要点：A、B 都只认 researchId → Redis；锁；读-改-写或 list 原子 append。
