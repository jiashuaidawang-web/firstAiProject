## 契约与安全

5. 工具入参 schema 从哪来？用户输入 `symbol=drop table` 时责任在模型还是在你的校验？

答：工具入参来源于LLM对用户输入的提取，如果用户未输入关键入参，LLM拿到确认tool的入参后，提醒用户输入对应的入参参数
如果用户输入了且输入的不对，且LLM没有识别出来不对，直接装入schema的param中，给到advisor，advisor在工具的入口是要做参数校验的，直接返回LLM参数有误，提示一个入参格式

6. 读工具超时：重试是 Advisor/HTTP 层还是工具里？写工具（本阶段没有）为什么默认不重试？

读工具超时，是什么意思，重试应该是advisor层把，默认只需要把真实结果给大模型就可以，大模型来决定换另外一个工具执行，而不是死等一个

7. MCP 是什么？本阶段为什么不实现它也能叫会了 Tool Calling？

MCP 是 model context protocol
是一个中规范，大家写tool要去遵守的
简单理解MCP就是对tool封装了一层

10. 口试 3 分钟：把工具当成不可信 RPC 客户端，你会加哪些和普通微服务一样的治理？
首先参数层面，我们要严格按照RPC服务端的要求来填写
调用超时，因为是网络波动，不能因为这个RPC迟迟未响应而死等，造成用户体验上的慢，应该快速失败，让大模型决策调用下一个方法
对调用失败的tool做个质量监控，比如Atool今天连续调用两次，都失败，advisor的tools注册表中就应该把他踢出，以免又调用到他
对相应的解析，不是200返回了就认为成功了，要有明确的业务含义的校验
